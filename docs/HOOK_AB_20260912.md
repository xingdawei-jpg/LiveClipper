## 最小改动

1. 第二遍从完整安全池比较真实 Hook 与紧接的 payoff。明确原话的可理解性、停留理由、新增信息和同一件商品的指代证据；不要求有疑问、反差或强情绪，也不允许默改 ASR。素材不足可报告 `limited`。
2. 删除“不得返回候选比较”的冲突要求，在原来的第二次调用内返回至多三组紧凑比较回执。顺序和短评由 AI 产生，不新增语义调用，不增加输出上限，不把候选自动插进片单。
3. `director_opening_audit.py` 只按实际安全池重建原文、时间和证据，检查 ID 合法性、重复、选中项及立即承接是否真的在播放前缀。`references_consistent` 仅表示引用一致；商品身份、吸引力和语义承接均保留 `human_review_required`。
4. 正常导演目录新增 `candidate_ledger.json` 与 `hook_candidates.json`；预览保留 `opening_selection`。已知回执不一致时，工作台显示“开场回执待复核”，不会仅凭 result 标签显示“开场已设置”。不自动换句或调整原片单。
5. 扩展安全测试发现原有 `content_review.py` 在 Python 3.11 中因 f-string 表达式内 Unicode 转义无法解析。只将八行中的转义字符串换成等价文字，没有改变规则、提示词输出或算法。修复后复放验证两遍请求与修复前完全相同。另将一个预览测试的临时目录断言改为 `.resolve()`，适应 Mac 的 `/var` → `/private/var`。

## 分项验收与未解决问题

- **ASR / 来源**：侧车有 30 个 ASR 段、969 个词，SRT 分成 65 行。质量报告初始及最终均零告警，但 #48「不是道」、#52「味来感」等仍需听原声确认，不能认为转写已正确。未做全片人工听写验收。字幕未改。
- **词级保真**：各轮实际预览句子及起止时间均与同 ID 原 SRT 完全一致；预览词条与原 `.words.json` 的文字和毫秒时间无不匹配。当前 sentence-preview 路径不调用 semantic binder/M3，这不是一次 M3 验收。真实首句删词后的剩余原话经后端验证；本地 UI 点词删除及撤销可用，测试操作已撤销。
- **候选安全**：已选 Hook 不含价格或库存催促，但整片安全不通过。基线含 #29「仓库里躺着了100单」；完整 B 还选入 #23、#32、#60 的库存/稀缺相关原话。在 block 合同下预览仍默认保留，调用现有导出硬过滤亦未删除。这是既有安全覆盖缺口，本轮未通过新增针对本视频的词表掩盖它。新增候选审计的“在安全池中”仅是来源边界，不是对真实内容安全的保证。
- **商品归属**：37、145、171 秒画面显示同一件皮夹克，可支持 13–58 中相关主商品段的局部判断；181 秒已在脱衣换款。#59–60 明说“刚才那件”，不能因都属 outerwear 就把其库存话术归给当前款。现有产品审计仍有待审项。静态抽帧不能证明每个代词的商品归属。
- **开头吸引力与后续承接**：配对 B 没有改变实际开头；完整 B 的比较理由与片单矛盾。所有 AI short review / quality 值均为待审声明，不是人工盲评，更不是完播率结论。
- **时长 / 视频**：用现有 Mac 源码审阅渲染器生成原速草稿，再按相同 1.15×生成审阅件。ffprobe 实测基线 25.966 秒、完整 B 34.966 秒，均可全量解码但低于 50 秒下限。帧/音频封装带来与字幕时长的小差异。只生成本机审阅视频，无发布；预览片单的库存风险仍在视频里，不能当作合格成片交付。

最值得后续处理的是：让同一轮 Casting 的所选开场真实成为最终片单前缀，同时更严格核实原句闭合与同款归属；按真实直播覆盖内容安全漏判。先补相应真实样本或人工标注，不以继续凑提示词、改原话、盲目扩时长替代质量判断。
